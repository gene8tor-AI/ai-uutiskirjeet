# Contributing

## Working model

1. Create an issue before work that changes product behaviour, operations, or deployment.
2. Use a focused branch. Keep unrelated changes out of the same pull request.
3. Update the README or `docs/` when setup, operations, environment behaviour, or deployment changes.
4. Never commit passwords, API keys, tokens, private customer data, or production environment files.
5. Run the repository's documented checks before requesting review.

## Pull requests

Each pull request should state:

- what changed and why;
- how it was verified;
- deployment or rollback impact, if any;
- documentation that was updated.

## Operational changes

Changes to DNS, production hosting, billing, permissions, secrets, or public URLs require explicit approval and a documented rollback path.
